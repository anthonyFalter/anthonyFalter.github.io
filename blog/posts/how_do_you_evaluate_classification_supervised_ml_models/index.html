How do you evaluate Supervised Machine Learning models using classification metrics?

August 18, 2026, 7:42 AM · Ross Elopre



As I was working on a small machine learning project about classifying each pixel's color in an image of a flower bouquet using K-Means algorithm to practice my skills, I have found that evaluation metrics differ from model to model. Metrics like Accuracy, Recall, and F1 only applied to my recent sandbox project in which I used naive bayes (GaussianNB) to predict NBA players that is likely to continue within 5 years using continuous features.

The evaluation metrics I used in the nba classification model however, didn't really apply to the pixel color clustering model. This is because of both model's innate nature, in which pixel clustering uses K-Means algorithm, which is an unsupervised learning model, while the NBA classification model is a supervised model.



Supervised? Unsupervised?

Supervised Learning is basically a type of machine learning that uses predictor/s and outcome variables in which, both variables must be labeled (already classified), and that the model should have a training (basically the student's answers to the test), and testing (basically the test's answer keys) data.

In Unsupervised Learning however, it doesn't have these testing and training datasets because it doesn't need one to begin with! one example is the pixel clustering project I made in which it clusters pixel colors using K-Means algorithm (More in-depth explanation about types of algorithms, and metrics used for each algorithm in later blogs) from the word cluster, it basically groups up every pixel based on their context using intelligent mathematical algorithms. So the reason unsupervised learning doesn't need testing and training datasets is because instead of predicting outcomes like how supervised learning works, unsupervised learning finds the hidden patterns, similarities within the dataset.



Key Classification Metrics used for Supervised Learning

In this part, I will be talking about the key classification metrics used for supervised learnings. I will be doing a comprehensive walkthrough towards their differences, when and where they are applied, and actual usage examples, so sit back and enjoy the show!

Types of classification metrics

  • Accuracy
  • Precision
  • Recall
  • F1
  • F-Beta

Not all metrics will be listed here like: ROC-AUC, Cross-Entropy Loss because I am planning to do an ever deeper dive on those topics in future blogs!



Confusion Matrix

Before diving into those metrics, we must first learn the foundation behind these terminologies. Confusion Matrix is basically a table used to evaluate the performance of a classification model. It compares predicted label against the actual labels and is split into 4 primary categories:

  • True Positive

    - The test result or prediction that is actually true and correct (matches the specified conditions).

  • True Negative

    - The test result or prediction that is actually false and is correctly classified as false (matches the specified conditions).

  • False Positive

    - The test result or prediction that is actually false but is categorized as true. (Does not match the specified condition, ex: patient doesn't have a deadly illness but is concluded to have one).

  • False Negative

    - The test result or prediction that is actually true but is categorized as false. (Does not match the specified condition, ex: patient does have a deadly illness but is concluded as none).



Classification Metrics

1. Accuracy

This metric basically answers: "Out of all the predictions made, how many were correctly classified?". This metric is generally used only on a balanced dataset (datasets with equal class importance)

Formula

\[ \frac{\text{TP} + \text{TN}}{\text{TP} + \text{TN} + \text{FP} + \text{FN}} \]

In the real world, a great example for this metric is: if a student has finished a quiz and the teacher is now checking that student's work, that teacher will compare the answers to an answer list:

  • Student's Answer: True | Correct: True (True Positive)
  • Student's Answer: False | Correct: False (True Negative)
  • Student's Answer: True | Correct: True (True Positive)
  • Student's Answer: False | Correct: True (False Negative)

We can see that the student got 3 answers correct, and 1 incorrect. In this scenario, by following the formula: \( \frac{2 + 1}{2 + 1 + 1 + 0} \), we get \( \frac{3}{4} \), which is .75 in decimal, or 75% in percentage

We just got the accuracy! But not all of the time accuracy is the baseline expectation for determining how accurate your model is. When the data is imbalanced, Accuracy falls short when the majority classes overshadow the minority.



An example for this is a: dataset with 100 entries about people with diseases. Imagine the entries of that dataset has 98 people are healthy, and only 2 of which does have diseases present. If you plug its values to the formula we used earlier, it will boast a 98% accuracy, but was it able to detect a single patient that has the diseases?

The answer is obviously no. It has shown accuracy, but accuracy treats every mistake as identical, which in our example, some errors carry far worse consequence than others. Even though the metric scored 98%, it presented a 0% ability to detect disease.

This issue, however, is answered by the next few classification metrics.



2. Precision

This metric answers: "Out of all the positive cases, how many were actually true?". This metric is used when the cost of false positive is high. One good example is for email spam algorithms in which a legitimate email that is not spam is flagged as a spam in which, the unlucky recipient might not end up receiving.

Formula

$$\frac{\text{TP}}{\text{TP} + \text{FP}}$$

An example for when precision is generally better to use is in: Content Moderation setups:

Suppose you are tasked to create an algorithm that will determine if a content is in violation of your company's terms and conditions, and the positive prediction is that the content reported is flagged as a violation, then that specific content will get banned. But in this case, if your false positive is a legitimate content getting banned wrongfully, this will result to poor user retention rate, while also destroying customer's trust.

This is where Precision comes in. By maximizing precision, you minimize the chances of false positives appearing. But by maximizing precision, you sacrifice recall, which will be introduced in the next part of classification metrics.



3. Recall

This metric answers: "Out of all actual positive cases, how many were correctly identified?" unlike Precision, in which the cost of False Positive is high, Recall measures the cost of False Negatives. You generally use Recall when you have zero tolerance for missed cases. A very, very good example for this are: Medical Diagnoses like cancer detections. Missing a patient that does have cancer can be fatal if not handled properly. Earlier in the Precision, I have mentioned that prioritizing one over the other will result in a trade-off. This is because Recall pertains to missing a real target whereas, Precision pertains to making a wrong guess.

Formula

$$\frac{\text{TP}}{\text{TP} + \text{FN}}$$

By prioritizing high Recall, you set your sights on not missing anything. However by setting such goals, you also drag in many negative cases, which causes False Positives to spike which, in the formula of Precision is on the denominator's side. So, what if you want to balance both metrics? F1 will then come to the rescue which will be explained in the next part.



4. F1-Score

F1 score, or F-measure, or the Harmonic mean of Precision and Recall, is basically a metric with the range of 0 to 1. It combines both Precision and Recall and heavily penalizes extreme imbalances in both metrics. Unlike accuracy which is only good for balanced datasets, F1 takes the crown for unbalanced datasets.

Formula

$$\text{F1-Score} = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

In the example for accuracy which is about 100 entries about people, and only 2 of the dataset actually have diseases, the Accuracy score would result in 98%, 98% in what exactly? But with the help of F1 metric, both Precision and Recall would return 0% and in turn, 0% F1 metric which means that the model failed to catch actual cases.

So, whenever you seeking to balance Precision and Recall because both metrics are important in your model, or because of reasons, I highly recommend experimenting with the F1-score!



5. Fβ (F-Beta)

This metric is fairly simple and complements F1-score really well. While F1-score weighs both Precision and Recall equally, Fβ allows prioritization of one of metric to your model. This is denoted by the symbol: β which is the weight chosen.

Formula

$$F_\beta = (1 + \beta^2) \cdot \frac{\text{Precision} \cdot \text{Recall}}{(\beta^2 \cdot \text{Precision}) + \text{Recall}}$$

By setting β = 1, you are basically telling the model to weigh both Precision and Recall equally. However, by setting it to β = 0.5, you setting Precision weights higher than recall, and β > 1 for when Recall is more needed than Precision



Conclusion

Never rely on a single metric, It is better to spread the eggs on different baskets rather than losing them all at once, in our case, missing out on very crucial data. Remember: Accuracy alone doesn't define how accurate your model is. A model with 98% Accuracy can easily hide a broken model.
